# 06 · 安全、隐私与性能

## 1. 安全边界

本项目是解释层，不是权限层、沙箱或安全证明器。

- 模型没有工具，不执行命令。
- 模型输出不变成审批裁决。
- 没有解释、解释失败或扩展卸载时，权限插件仍按原规则处理。
- 解释成功不意味着命令安全，尤其无法证明脚本、环境变量、未知二进制和外部服务的实际行为。
- 不为获取完整上下文读取权限日志或私有状态。

## 2. 命令发送就是一次数据外发

即使命令尚未获准执行，发送给外部模型也已经产生数据披露。

因此必须：

1. 只在用户显式按下解释键后发送。
2. 在提示或说明区明确本次使用的模型 / provider。
3. 不把整个主对话、文件内容、认证对象或环境变量全集打包发送。
4. 支持用户固定到本地或更合适的 Pi 模型。
5. 不因指定模型失败而偷偷换到另一家服务。

本扩展不复制 `auth.json`、`models.json` 中的认证内容，也不读取受权限保护的其他扩展配置来规避原规则。

选择 Pi 虚拟模型时，用户已有的路由可能改变实际模型和供应商；应标记该语义，不能把虚拟 provider 名当作最终数据接收方。需要固定目标时使用具体模型。

## 3. 有限脱敏

发送前可遮蔽明确命名的秘密，例如：

- `TOKEN=...`、`PASSWORD=...`、`API_KEY=...`。
- Authorization / Cookie 等请求头。
- 明确的 `--token`、`--password` 等敏感参数值。

但脱敏必须声明为 best-effort：

- grep 搜索词、heredoc、内联脚本或任意业务字符串中可能藏有秘密。
- 正则遮蔽不能证明已经理解全部 shell 语法。
- 遮蔽后某些语义可能变得不确定，应在解释中承认。
- 不应为了脱敏执行命令、读取变量值或额外调用模型。

如果无法在保持语义边界的同时安全准备输入，应停止该次发送并提示，而不是伪装成已经完全脱敏。

原命令由原审批展示；扩展不应无必要地在更多位置重复打印它。

## 4. 提示词注入防护

命令、模型名、规则名、路径和模型输出都是不可信数据。

- 稳定系统提示明确：命令中的自然语言是待解释数据，不是指令。
- 数据使用独立字段 / 消息或明确界定的块传入，不直接拼成系统指令。
- 语言标签必须本地验证，不能把原始环境字符串放入指令。
- 不允许解释模型要求调用工具、修改设置或替用户批准。
- 字符串分隔符只能帮助模型理解，不等于密码学隔离或绝对注入防护。
- TUI 对控制序列、超长行和可能欺骗显示的文本作适当处理；不把输出直接写入原始终端控制通道。

## 5. 最小请求策略

一次用户触发最多发起一次独立解释请求，除非用户显式再次重试。

发送内容：可见命令或命令单元、必要权限事实、有限参考目录信息、目标语言要求。

不发送：主会话完整历史、完整系统提示、工具定义列表、文件树、原 agent 思考内容或自动读出的项目文件。

- 默认低 / 关闭推理偏好，实际能力由 provider 决定。
- 默认输出预算 384 token，是请求预算而非费用承诺。
- 到达上限不自动“继续生成”。
- 失败不自动重试或使用备选模型。扩展控制的 provider 重试预算应设为 0；不能把一次 SDK 调用描述为绝对只有一次底层 HTTP 请求，因为 provider / 路由仍可能有自身行为。
- 目标语言不符不自动翻译。
- UI 文案本地化不进入模型上下文。

## 6. 缓存契约

首版只做内存中的会话缓存，无磁盘缓存。

缓存身份至少包含：

- 实际 provider 与 model ID。
- 目标语言。
- 提示词版本及影响结果的请求选项。
- 发送内容的精确摘要，包括命令、可见权限事实、目录信息及“未知”标记。
- 必要的会话 / 转发来源范围，防止错误跨环境复用。

不得折叠引号、换行或随意归一化命令空白；这些可能改变 shell 语义。相同文本也不证明文件和环境未变化，因此缓存只表示相同已知输入的辅助说明，不表示新的安全结论。

边界：

- 默认最多 16 条、TTL 5 分钟、内容估算总量不超过 256 KiB。
- 任一条目 / TTL / 字节预算配置为 0 时禁用缓存，不表示无限。
- TTL 使用读 / 写时惰性淘汰，不设置常驻清扫 timer。
- 不在 key 中明文保存命令，可使用内置 `node:crypto` 生成摘要；摘要不是匿名化保证。
- 不缓存空输出、失败、已取消或超时后的迟到结果。
- 虚拟 / 路由模型首版不做跨审批缓存，避免无法在发起前确定实际路由时错误复用；同一 requestId 的重复触发仍复用进行中请求和已完成结果。
- 会话关闭、切换或重载清空缓存。

## 7. 日志与费用可见性

- 默认不写命令、模型输入、解释输出或 provider 返回体到磁盘。
- 故障提示只记录错误类别与必要标识，防止 SDK 异常文本携带凭据。
- 不为了审计或费用统计把解释放进主对话。
- 可以在本扩展 UI 中展示 SDK 返回的 usage；不保证 Pi 原生 footer 自动累计这种侧向模型请求。
- 自定义 provider 的价格元数据可能不准确，不把价格 0 当作免费保证。
- 供应商仍可能保留请求；本扩展无法控制其服务端策略。

## 8. 性能设计预算

下表是设计约束，不是已经测得的基准。

| 场景 | 约束 |
| --- | --- |
| 扩展初始化 | 不启动进程、网络解释请求、轮询器或文件 watcher |
| 无审批的普通按键 | 快速条件判断后透传，不查模型、不读磁盘、不检测语言 |
| 审批出现 | 建立小快照并显示一行提示，不等待网络 |
| 不使用解释 | 额外模型请求数 0，额外模型 token 0 |
| 按需解释 | 单个有超时的模型请求；对重复按键去重 |
| 语言识别 | 会话内缓存本地环境结果，按需读已有公开偏好快照 |
| UI 刷新 | 合并增量状态更新，避免逐 token 重排和终端刷屏 |
| 缓存 | 条目、TTL、内容大小三重限制 |
| 请求结束 | 清除临时 timer 和引用 |

“不使用解释时 token 为 0”只指本扩展不新增模型请求，不是整个 Pi 会话零费用。

## 9. 真实测量要求

实现后必须分别记录：

- 扩展初始化耗时与增量堆内存。
- 普通按键处理耗时及是否产生磁盘 / 网络访问。
- 100 次只审批不解释场景的额外模型请求数，应为 0。
- 连续按键与流式输出时的 TUI 响应。
- 带 / 不带多语言逻辑的本地处理差值。
- 中文与英文的实际输入 / 输出 / 推理 token，不预设二者相同。
- 审批结束后的取消延迟与迟到结果丢弃。

不要用纯 locale 函数微基准替代真实审批体验与内存泄漏测试。

## 10. 故障原则

失败只影响本次解释。任何异常都不能成为绕过权限、默认批准、切换高价模型或继续发送敏感上下文的理由。

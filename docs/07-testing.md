# 07 · 测试与验收

## 1. 测试层次

1. **单元测试**：纯函数、配置、语言解析、模型策略、缓存和控制器状态。
2. **契约 / 集成测试**：用 Pi 与权限事件的有界 fixture 验证接入，不访问真实供应商。
3. **真实 TUI 验收**：在实际 Pi 与权限插件版本下检查按键、焦点、队列和取消。
4. **显式模型烟测**：用户同意后，用选定模型检查真实输出与费用。

默认测试不得需要 API Key、网络连接、付费模型或修改用户现有 Pi 配置。

## 3. 单元测试明细

### 3.1 配置

- 文件缺失时默认值与文档一致。
- `explanationModel: null`、缺省、合法固定模型三类分开处理。
- 模型字段损坏不被当作 null。
- 快捷键严格校验，不因错误修饰符退化成裸字母。
- 数值预算边界、非法 JSON、非对象、未知字段保留策略。
- 原子保存成功后才更新内存；写入和 rename 失败时旧配置有效。
- 手动修改在下一次按需读取时生效，不需要 watcher。

### 3.2 模型策略

- 同名模型不同 provider 不混淆。
- 模型 ID 含 `/` 不被拆坏。
- 可用聊天模型与图像 / 分类模型分开。
- 模型列表不被当前 scoped 子集意外限制。
- 固定模型不可用、无当前模型、主模型运行中切换。
- 全流程断言没有调用 `setModel()` / `setThinkingLevel()`。
- 选择列表、保存模型均不调用聊天推理接口。
- 虚拟模型明确标记路由语义，不以虚拟名称保证实际费用或 provider。
- off / low 推理偏好在支持的 provider 上按公开参数验证，不把未设置选项误当关闭。
- 适配器可控制的 provider 重试预算为 0，失败不发起扩展层第二次调用。

### 3.3 事件投影与并发

- 畸形 payload、空 requestId、缺字段、错误字段类型。
- bash 命令审批与路径审批中顶层 value / request.value 的区别。
- bash 外部路径审批（`bash_external_directory`）的 value 与 request.value 同为命令全文，靠 decidingPath 区分，不因等值误判为只有路径。
- 命令单元与全文不可区分时采用保守范围说明。
- `requestId` 不等于 `toolCallId`，不能依赖缺失字段。
- 同一命令文本的两个审批请求仍分别管理。
- 一个工具调用触发多个 gate，不因文本相同错误合并。
- 排队请求只有 ui_prompt 后才成为当前可见目标。
- 转发请求缺工作目录时标记未知，不复制父 cwd。
- 不支持的工具 / 别名 / 只有路径的事件不发送猜测命令。

### 3.4 控制器与资源

- repeated trigger、model error、timeout、abort、late success、late error。
- 每个结束分支都释放 timer 和流监听。
- session shutdown / reload / replacement 清理订阅、widget 和缓存。
- 旧 generation / attempt 结果无法写入新状态。
- 断言没有启动子进程、创建 agent session 或发送主会话用户消息。
- 空结果与截断结果不能被误当完整说明。

### 3.5 缓存

- 模型、provider、语言、提示词版本、目录及发送事实变化都影响 key。
- 引号、换行、空白不被随意折叠。
- 条目、字节与 TTL 限制生效；0 表示关闭，不代表无限。
- 惰性淘汰，无常驻清扫 timer。
- 失败、取消、空输出不缓存。
- 本会话结束清空，磁盘上没有命令缓存。
- 虚拟模型不跨审批命中缓存，同一请求的重复按键仍被去重。

## 4. 多语言矩阵

| 输入环境 | 期望 |
| --- | --- |
| 显式 `language: "ja"`，系统 zh-CN | 输出目标 ja |
| auto，公开 rpiv 快照 locale=de | 输出目标 de |
| auto，公开快照 locale=undefined，Intl=zh-CN | 继续检测并得到 zh-CN |
| auto，公开快照 locale=en | 尊重明确 en |
| `LC_ALL=fr_FR.UTF-8`，`LANG=en_US.UTF-8` | 目标 fr-FR |
| `LC_ALL=C.UTF-8`，Intl=zh-CN | 目标 en |
| LANGUAGE 多项偏好 | 取首个有效标签 |
| 无环境变量，Intl=zh-CN | 目标 zh-CN |
| `zh-TW` / `zh-Hant-HK` | 保留繁体语义 |
| 非法环境 locale | 继续回退，不把原字符串放入提示词 |
| 非法显式配置 | 提示修复，不伪装成默认 |
| Intl 无法获取 | 最终回退 en |
| ja 无 UI 字典 | UI 可英文，解释目标仍 ja |
| 请求中切换语言 | 不重发当前请求，下一次用新语言 |

单元测试通过 mock 固定 `process.env` 与 Intl，避免依赖运行测试机器的真实语言；测试后必须恢复环境。

提示词测试断言目标标签、程序标识不翻译、已脱敏值不被恢复和单段纯文本约束，不用额外 LLM 做自动裁判。

## 5. 真实 TUI 验收清单

必须覆盖普通 / 全屏两种模式，至少在目标 Windows 终端实测：

- Alt+E 是否能到达 Pi，是否被 IDE / 菜单截获。
- 审批组件聚焦时是否有效，而非只在主编辑器有效。
- 非审批状态按键是否原样透传。
- y / s / n / r、Enter、Esc、Ctrl+O 原行为是否保持。
- 拒绝理由输入和中文 IME 是否受影响。
- 原审批超时在解释生成过程中仍符合原规则。
- widget 是否可见，是否抢焦点或遮挡原审批。
- 窄屏、CJK 宽字符、resize、主题、长模型名与多行说明。
- 两个排队审批、转发子会话请求及父子相同命令。
- 重载与退出后是否残留说明、监听或无法结束的 Promise。

仅用模拟广播不能证明原审批 UI 的真实兼容性；仅检查源码也不能代替此项。

## 6. 真实模型烟测

由用户明确选择模型并同意可能的费用后执行，默认关闭。

推荐检查：

- 简短只读命令能输出一句话说明。
- 破坏性参数有清晰提醒，不自动批准。
- 项目脚本和未知变量被标记为上下文不足。
- 中文、英文、繁体等至少两种目标语言。
- 固定模型失败时没有第二次自动请求。
- 输出达到预算后没有自动续写。
- 记录返回的 input / output / reasoning usage；不默认保存原命令。

模型的语言服从性和语义准确度需要人工抽查，不能以“API 返回成功”替代质量验收。

## 7. 性能与隐私验收

- 连续 100 次只审批、不解释：本扩展聊天请求数 0。
- 打开设置、搜索模型、切换语言：无解释推理请求。
- 普通键盘输入不读配置文件、不创建网络请求。
- 检查 timer、订阅、缓存和流对象在多轮后是否回收。
- 检查本扩展未写主会话消息、认证文件、权限配置或命令日志。
- 对不同语言测量实际 token，不给出“多语言完全无额外 token”的错误结论。
- 供应商取消后的费用行为只作观察记录，不作零计费保证。

## 8. 发布门槛

以下全部通过后才能称为可用版本：

- 类型检查、格式 / lint、默认离线测试通过。
- 模型与语言配置失败策略有测试。
- 目标版本真实 TUI 验收通过。
- 至少一次用户授权的模型烟测通过。
- 打包清单包含 src 与 locale 字典，排除缓存、密钥和测试敏感 fixture。
- README 标明支持版本、命令范围和已知限制。

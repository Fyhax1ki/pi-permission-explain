# 01 · 需求与范围

## 1. 背景与目标

权限审批解决“是否允许”，但用户仍可能看不懂被审批的 shell 命令。每次审批都自动调用模型会增加成本与等待，也会让熟悉命令的用户受到干扰。

本项目采用按需解释：正常审批没有额外模型请求，用户主动触发时才获得一段简短说明。

## 2. 硬约束

- 不修改权限插件源码，不依赖 monkey patch 或私有 UI 状态。
- 不自动授权，不改变原权限规则、审批按钮或审批结果。
- 不启动第二个 agent，不给解释模型提供工具。
- 不把解释作为新的用户消息提交给正在等待审批的主会话。
- 项目结构清晰，代码职责单一、类型明确、注释解释原因和边界。
- 配置既能由 TUI 修改，也能手动编辑并持久化。
- 多语言不得通过额外的语言识别或翻译模型请求实现。

## 3. 用户故事

### U1：看得懂的命令直接处理

用户看到熟悉命令，按原有操作允许或拒绝。扩展不等待模型，不弹出额外确认，不增加主模型上下文。

### U2：看不懂的命令主动解释

待审批期间按 Alt+E，原审批继续有效，旁边显示生成状态及短说明。说明不等同于批准。

### U3：昂贵主模型搭配便宜解释模型

用户在扩展设置中看到 Pi 已添加的可用模型，选一个更便宜的模型。此后解释请求使用该模型，主会话模型不变。

### U4：不设置专用模型

解释模型选择“跟随当前模型”。用户切换主会话模型后，下一次解释使用新的当前模型，不需要重新配置。

### U5：跟随本地语言

中文环境默认输出中文解释；其他环境尽力使用相应语言。检测不符合偏好时，用户可在设置中明确指定语言。

## 4. 功能要求

## 5. 模型列表的精确定义

“Pi 已添加模型”是指**Pi 模型注册表已识别的聊天模型**，不是项目维护的静态模型名单。

- 可选列表默认展示 `ctx.modelRegistry.getAvailable()` 返回的可用聊天模型。
- 可以额外用 `getAll()` 展示已识别但不可用的模型，并明确标注、禁止直接选用。
- 不只显示当前模型，不只取当前会话的 `scopedModels` 子集。
- 自定义 `models.json` 模型和 provider 扩展模型，在已加载到注册表后应能出现。
- 分类模型、图像生成模型不作为自然语言解释模型列入。
- “有认证”不保证请求一定成功；网络、配额、服务端模型权限仍可能失败。
- 用户自行选择更便宜的模型；本项目不根据可能缺失或不准确的价格元数据自动选择“最便宜模型”。
- 虚拟 / 路由模型须明确标记，其实际模型、费用和数据接收方由路由规则决定。希望固定低成本与发送目标时，应选择已配置的具体模型，不能把虚拟模型名称当作费用保证。

## 6. 解释内容

默认只输出一段纯文本：用一两句话说明命令或当前命令单元试图完成什么，不写标题、列表、编号或 Markdown 标记，也不单列“注意事项 / 建议 / 安全提示”段落。命令涉及删除、覆盖或其他不可逆改动时，在该句中直接点明；需要读取、写入或联网时同样并入正文。

禁止把解释写成权威安全结论，例如“绝对安全，可以放心批准”。对于脚本、变量、未知程序、缺失工作目录，必须承认不确定性。

命令、参数、路径、URL、环境变量名和程序标识不作语言翻译；只翻译解释性文字。发送前的安全脱敏仍然生效，已脱敏值不要求模型恢复或照原文泄露。

## 7. 支持范围与降级

### 首版范围

- Pi 交互式 TUI，普通模式与全屏模式都需要验收。
- 原生 `bash` 审批及能够由公开事件可靠识别的 shell 审批。
- 本地请求，以及在父会话中实际显示的转发请求。
- 公开事件中可见的命令 / 命令单元及权限事实。

### 必须公开说明的限制

- 公开 `ui_prompt` 不携带完整工具输入、完整 evidence、稳定的 `toolCallId` 或子会话工作目录。
- 普通 bash 规则审批可能只暴露被拦的命令单元，而非整条命令链。
- 转发请求的当前父会话目录不能冒充子会话执行目录。
- 不认识的 shell 别名、只有路径的事件或缺少命令的事件，显示“不支持或上下文不足”，不猜测关联工具调用。
- 不承诺首版支持 PowerShell、所有 MCP 工具语义或任意非 shell 工具的完整解释。

上述限制不能通过读取审计日志、模糊匹配并发工具输入或访问私有 UI 对象“补齐”。

## 8. 非目标

- 替代沙箱或确定性权限引擎。
- 自动批准、自动拒绝、自动改写命令或重试主任务。
- 在原审批菜单内追加可上下选择的原生菜单项。
- 注入 Pi 核心 `/settings` 页。
- 启动时扫描项目、自动读取脚本内容、执行 `--help` 或运行命令验证效果。
- 从 IP、地理位置、用户名、聊天记录或密钥推断用户语言。
- 为模型不遵循目标语言而自动追加翻译请求。

## 9. 非功能要求

| 编号 | 要求 |
| --- | --- |
| NFR-01 | 未主动解释时，扩展额外 LLM 请求数为 0 |
| NFR-02 | 待审批展示不得等待解释模型网络请求 |
| NFR-03 | 不常驻启动子进程、文件 watcher、轮询器或语言服务 |
| NFR-04 | 缓存、输入与输出有界，退出和重载能释放资源 |
| NFR-05 | 错误不破坏原审批；失败只影响本次解释 |
| NFR-06 | 不复制认证配置，不默认落盘命令或模型输出 |
| NFR-07 | 接口边界使用 `unknown` 验证，内部使用明确类型和判别联合 |
| NFR-08 | 语言与模型配置变更后下一次请求生效；进行中的请求使用启动时快照 |

验收映射见 [测试与验收](07-testing.md)。

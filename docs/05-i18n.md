# 05 · 多语言设计与可行性分析

## 1. 结论

**能够实现，采用纯本地语言线索识别时，新增运行负担很小。**

本功能不需要语言识别模型，不需要网络翻译服务，不需要额外 agent。命令解释本身已是模型请求，只需在这个请求中明确目标语言。

准确表述是“少量增量开销”，不是“完全零成本”：

- 本地解析需要少量 CPU 与对象分配。
- UI 字典需要少量内存。
- 语言要求增加少量输入 token。
- 不同语言本身的 token 切分不同，输出消耗可能变化。

尚未实现与基准测试，不应给出虚构的毫秒或内存测量结果。

## 2. 本机检查及其意义

本次运行了只读的 Node 环境检查，结果为：

```text
platform: win32
node: v24.21.0
Intl locale: zh-CN
LC_ALL: unset
LC_MESSAGES: unset
LANGUAGE: unset
LANG: unset
```

这说明 Windows 环境不能只查 `LANG` 或 `LC_ALL`。若仅采用 Unix 环境变量再回退英文，本机就可能得到错误的默认语言。

`Intl` 返回的仍是 Node 运行环境默认 locale，可能与系统显示语言、用户母语或阅读偏好不同。SSH、容器、WSL 中也可能得到远程或容器语言，而不是宿主机偏好，所以必须允许显式配置。

## 3. 输出语言与 UI 文案分开处理

虽然配置使用同一个 `language` 偏好，内部仍需区分两层：

1. **目标解释语言**：传给模型的语言标签。
2. **UI 字典选择**：本扩展是否有对应文案包。

例如目标语言是 `ja-JP`，但扩展尚无日文 UI 字典：

- 模型仍被要求输出日文。
- 设置和状态文案可回退英文。
- 不得因为 UI 回退英文，就把解释目标语言改成英文。

首批 UI 字典：`en`、`zh-CN`。其他语言的模型解释能力取决于用户选定模型，不代表已有完整 UI 翻译和人工校对。

## 4. 本地解析优先级

这是本项目明确定义的策略，不声称完全复刻操作系统或 GNU gettext 的所有 locale 规则。

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 本扩展显式 `language` | 不是 auto 时优先；非法值提示修复 |
| 2 | 已存在的可选 rpiv-i18n 公开快照 | 非空、合法 active locale 时尊重已有 UI 偏好 |
| 3 | `LC_ALL` | 有效值；明确 C / POSIX 解释为英文偏好 |
| 4 | `LC_MESSAGES` | 有效消息语言 |
| 5 | `LANGUAGE` | 按冒号分隔，从左到右取首个有效偏好 |
| 6 | `LANG` | 有效 locale 值 |
| 7 | `Intl.DateTimeFormat().resolvedOptions().locale` | 重要的 Windows 与无环境变量兜底 |
| 8 | `en` | 最终可预测回退 |

补充规则：

- 环境值为空或非法时继续下一来源，不把原始字符串直接写入提示词。
- `C`、`POSIX` 及其编码变体作为明确英文 locale 处理，而不是根据地区再次猜测。
- 自己的显式配置错误不能当作缺省值静默回退。
- 结果保留来源枚举，供设置页显示，不发送整份环境信息。

## 5. 规范化与语言粒度

本地规范化流程：

1. 限制输入长度并去除外围空白。
2. 对环境格式去掉 `.UTF-8` 等编码后缀。
3. 将标准 `<language>_<REGION>` 分隔转换为 BCP 47 风格。
4. 对已知的 POSIX modifier 明确转换；未知 modifier 不盲目解释。
5. 使用 `Intl.getCanonicalLocales()` / `Intl.Locale` 验证并规范化。
6. 用语言、脚本和地区组成的基础标签作为目标，丢弃日历、数字格式等无关扩展。

需要保留的例子：

| 输入 | 目标语义 |
| --- | --- |
| `zh_CN.UTF-8` | `zh-CN`，简体中文 |
| `zh-TW` | `zh-TW`，繁体中文 |
| `zh-Hant-HK` | 保留 Hant 与 HK，不折叠成简体 |
| `pt_BR.UTF-8` | `pt-BR`，保留地区差异 |
| `en_US.UTF-8` | `en-US` |
| `C.UTF-8` | `en` |

UI 字典匹配按精确标签、适用脚本 / 基础语言、英文回退处理。没有繁体字典时，不应把简体 UI 伪装成完整繁体支持；模型解释仍保留繁体目标。

## 6. 可选 rpiv-i18n 集成

本机已安装 `@juicesharp/rpiv-i18n 2.15.0`。其文档公开了只读快照：

```text
globalThis[Symbol.for("rpiv-i18n")]
  → { locale, namespaces }
```

轻量实现优先只读该公开快照。它是当前进程的共享偏好，不保证按会话隔离；同进程不同会话若有不同语言要求，应使用本扩展显式配置，不把进程快照误称为会话私有偏好。

- 不要求用户安装此包，不新增强制依赖。
- 不改写全局 locale，不调用 `applyLocale()`。
- 不访问私有 `rpiv-i18n.runtime`。
- 不为了获取语言而导入可能带初始化副作用的扩展入口。
- 快照缺失、locale 为 undefined 或非法时继续自身本地解析链。
- 在需要语言的时刻读取最新快照，不永久缓存快照对象引用。

特别注意：该 SDK 的 `undefined` 表示英文默认 / 未明确设置，不能当作用户明确要求英语而覆盖本机 `Intl` 的 `zh-CN`。

该包当前检测链主要依赖配置及 `LANG` / `LC_ALL`，没有代替本项目处理 Windows `Intl` 兜底。

如果已有 `/languages` 设置改变，本扩展下一次解释应读取新语言；进行中的请求继续使用启动时快照，不自动重发。

## 7. 模型提示词策略

基础行为提示保持稳定英文，另外附加一个短的、经过本地验证的语言要求。例如：

```text
Write the explanation in Simplified Chinese (zh-CN).
Keep command text, flags, paths, URLs, environment-variable names,
and program identifiers verbatim. Translate only explanatory prose.
Explain purpose, effects, and uncertainties. Do not authorize execution.
```

未知但合法的语言标签可以使用规范标签和 `Intl.DisplayNames` 的显示名称，不依赖外部语言表或调用模型翻译语言名。

不得：

- 先调用模型判断语言，再调用模型解释。
- 先输出英文，再默认调用翻译模型。
- 为了检测语言读取整段聊天记录或项目内容。
- 本地化程序标识、配置键、内部 sentinel 或命令参数。
- 承诺任何廉价模型都能可靠生成所有语言。

保留标识原文仅指不翻译。安全脱敏优先：模型只能看到并引用脱敏后的文本，不应恢复秘密值。

模型不遵循语言要求时，默认显示原结果并允许用户显式调整或重试，不自动增加请求。

## 8. 缓存与生效

- 系统环境 / Intl 的解析结果在会话初始化时缓存，刷新设置或重建会话时重新解析。
- 可选公开语言快照可在触发和必要渲染时作 O(1) 读取。
- 显式配置在保存后下一次请求生效。
- 解释缓存必须包含解析后的语言标签和提示词版本。
- 不能把同一命令的中文解释当作英文缓存命中。
- 语言改变不启动后台重译，也不改写已完成的主会话内容。

## 9. 增量开销评估

| 环节 | 多语言新增工作 | 控制措施 |
| --- | --- | --- |
| 初始化 | 少量环境变量读取、一次 Intl 查询、规范化 | 缓存结果，不调用系统子进程 |
| 普通按键 | 不需要语言分析 | 无请求则直接透传 |
| 审批提示 | 显示本地化短提示 | 字典查表，不发网络请求 |
| 主动解释 | 读取有效语言，增加一小段语言约束 | 与原解释合并成一次请求 |
| 设置页 | 显示语言名与来源 | 本地 Intl，不下载语言包 |
| UI 渲染 | 本地字典查表 | 只在状态变化时刷新 |
| 语言切换 | 更新偏好或读取新快照 | 不自动重做此前解释 |

因此对“轻量、无感”的目标影响有限。真正的大头仍是用户主动触发后的模型网络延迟与推理 / 输出消耗，而不是本地语言检测。

## 10. 必测项

- 本机这种无 LANG 的 Windows 环境检测为 `zh-CN`。
- Linux / macOS 有 `LANG` 的场景，以及 `LC_ALL` 覆盖。
- `C` / `POSIX`、损坏 locale、缺少 Intl 查询结果的回退。
- 简体、繁体、地区标签保留。
- SDK 存在 / 缺失 / undefined / 显式 en / 动态切换。
- UI 回退英文时，模型目标语言保持不变。
- 语言提示不翻译程序标识；安全脱敏后的值仍保持遮蔽，不要求恢复秘密。
- 语言切换后旧缓存不误命中、旧请求不被自动重发。

完整矩阵见 [测试与验收](07-testing.md)。

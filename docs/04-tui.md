# 04 · TUI 与交互

## 1. 交互原则

- 默认无额外步骤，用户不需要解释时按原方式处理。
- 按需解释不等于新增一道授权流程。
- 说明是旁挂内容，原审批组件始终由权限插件管理。
- 不通过 Esc 关闭说明，因为原审批可能将 Esc 解释为拒绝。
- 不使用普通 `e` 或其他裸字母，减少中文输入法及拒绝理由输入冲突。

## 2. 审批时的默认展示

以下是布局示意，不代表插入原菜单内部。

```text
原权限审批框
  命令 / 路径、规则及原有允许、拒绝等操作……

Alt+E：解释命令 · 模型：跟随当前模型 · 语言：简体中文
```

选择固定模型后，提示应显示简短模型标识，方便用户知道命令会发送到哪里。空间不足时缩短显示文本，不改动实际模型引用。

非 shell 请求或信息不足时不显示误导性的“可解释完整命令”提示；可显示简短不可用原因，且按键不会产生模型请求。

## 3. 生成与展示

```text
Alt+E：正在解释…… · 选定模型 [provider]

用途：……
影响：……
注意：……

模型生成的辅助说明；请结合原命令自行决定。
```

- 输出流式更新，但节流渲染，不要求每个 token 重排整个 TUI。
- 说明保持短小，默认控制在三项摘要内。
- 原审批按钮仍可操作，不必等解释完成。
- 用户批准或拒绝后，扩展取消请求并清理说明。
- 已完成的同一请求再次触发只展示已有结果，不重复花费。
- 失败后再次按键是用户显式重试；不自动重试。
- 不把 Markdown 代码块当成可执行动作，也不让模型定义交互按钮。

## 4. 快捷键实现与边界

使用 `ctx.ui.onTerminalInput()`，在数据进入聚焦审批组件前识别 `matchesKey(data, configuredKey)`。

输入处理顺序：

1. 扩展关闭、非 TUI 或没有当前审批：立即透传。
2. 排除按键释放、粘贴内容和不相关输入。
3. 仅精确匹配已校验的组合键。
4. 有匹配且当前请求可解释：同步消费按键，异步启动或复用解释。
5. 所有其他按键原样透传。

不要只依赖 `pi.registerShortcut()`：本机核查显示普通扩展快捷键主要挂在编辑器上，审批自定义组件聚焦时不应假设它能穿透。

也不要为了占用诊断额外注册一个相同的全局 shortcut，导致非审批状态下编辑器吃掉 Alt+E。

### Alt+E 占用核查结论

- Pi 已查默认键位未占用。
- 已查已安装扩展代码及默认绑定未发现显式占用。
- 当前 agent 目录未发现 `keybindings.json`。
- `agent/web-search.json` 的用户覆盖因权限规则禁止读取，未检查、未绕过。
- 终端、IDE、输入法或其他原始输入监听仍可能抢先处理。

所以默认 Alt+E 的结论是“合理候选，待真实按键验收”，不是全系统无冲突保证。保留可写配置供用户改键，不承诺自动枚举其他扩展所有 raw listener。

### 超时注意事项

消费解释键不保证触发原审批内部的“用户已交互”逻辑。若原权限插件设置了审批超时，解释过程仍可能被超时结束。遵守原语义，不伪造原菜单操作。

## 5. 设置入口

计划命令：

```text
/permission-explain-settings
```

这是扩展自己的 TUI 设置界面，不向 Pi 核心 `/settings` 注册新条目。设置通常在正常输入状态打开，不要求在聚焦的审批框中输入斜杠命令。

首屏示意：

```text
命令解释设置

启用解释        开启
解释快捷键      Alt+E
解释模型        跟随当前模型  ›
语言            自动（当前：简体中文）  ›
高级设置        ›

↑↓ 选择 · Enter 修改 · Esc 返回
```

展示当前解析出的语言及其来源，如“系统 Intl”，便于纠正检测结果。不得在界面上泄露环境变量全集或认证信息。

## 6. 模型选择器

```text
选择解释专用模型

搜索：

● 跟随当前模型（默认）
○ 模型 A [provider-a]
○ 模型 B [provider-b]
○ 模型 C [provider-c]

只影响命令解释，不切换主会话模型。
```

### 行为契约

- 首项是稳定 sentinel，例如内部 ID `__current__`，不要拿翻译后的文本作分支条件。
- 其余行来自 Pi 模型注册表，显示模型 ID、名称及 provider。
- 默认展示全部已配置可用聊天模型，不局限于主会话模型循环范围。
- 允许搜索模型名、模型 ID 和 provider。
- 先显示现有快照；需要更新时由用户刷新或在打开面板时有界刷新元数据。
- 不调用 LLM 生成或排序模型名单。
- 已知虚拟 / 路由模型标明“由 Pi 路由”，提示不能由显示名称保证实际费用或数据接收方。
- 不可用的已保存模型显示“不可用”，保留引用，不自动勾选“跟随当前模型”。
- 保存成功后返回设置页；保存失败保留旧值并解释原因。
- 列表中的所有名称视为不可信显示数据，需要处理控制字符与超长文本。

不因用户选择解释模型而调用 `pi.setModel()`，也不修改主模型思考强度。

## 7. 语言选择器

最少提供：

```text
自动（当前检测：zh-CN，来源：Intl）
简体中文（zh-CN）
繁體中文（zh-TW）
English（en）
输入其他语言标签……
```

手工标签经本地验证后保存。列表文案能本地化，但内部持久化为语言标签，不保存“简体中文”这类显示名称。

首版扩展 UI 字典提供英文与简体中文；解释输出的目标语言不受 UI 字典数量限制。

## 8. 错误反馈

| 场景 | 提示与动作 |
| --- | --- |
| 固定模型不可用 | 显示模型引用与不可用原因，不切换到贵模型 |
| 无当前模型 | 提示先配置或选择模型，不调用接口 |
| 请求超时 | 显示超时，可显式重试，原审批保持其自身状态 |
| 上下文不足 | 说明当前能看到什么，不能保证完整命令语义 |
| 输入过长 | 不发送，明确告知限制，不自动压缩或截断 |
| 模型返回空文本 | 显示失败，不把空说明当成功缓存 |
| 输出达到上限 | 标注内容可能不完整，不自动追加“继续”调用 |
| 语言不符合目标 | 不自动翻译，允许用户调整语言 / 模型 |
| 审批结束 | 清理 UI；迟到结果不再展示 |

## 9. 模式适用性

- 普通 TUI 与全屏 TUI 都使用同一套按需按键逻辑，必须分别验收。
- 首版不以鼠标按钮为验收前提；全屏模式可在后续添加等价点击入口。
- print / JSON / RPC 不安装 TUI 交互监听；解释业务与渲染应分离，为未来前端入口保留可能。
- 需测试窄屏、中英文混排、组合字符、resize、主题切换、IME 及键盘布局差异。
